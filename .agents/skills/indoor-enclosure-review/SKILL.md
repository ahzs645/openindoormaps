# Indoor enclosure review

Use the loaded/canonical project as evidence, recover the actual native enclosure, and preserve the source-to-prepared pipeline. The review interface is **Room review** in `/projects/indoor`; its live worker audit uses the same detector as `indoor:audit-volumes`.

Read [the review workflow](../../../docs/indoor-enclosure-review.md) for the task's relevant failure cases, commands and source/compiler entry points. The sibling Reviter repository supplies native geometry extraction and regeneration; read its `docs/indoor-project-pipeline.md` when changing source annotations or recompiling.

## Decisions that matter

- A missing volume is not automatically a wrong elevation. Check actual visitor blocks in both ordinary and native-height modes, all relevant campus/native scopes and first-click selection. Count room keys once across overlapping scopes.
- Classify deliberately flat circulation, staff areas, stairs and voids separately from unsupported room enclosures. A name or proximity pin alone does not prove an enclosure, a restriction boundary or a served connector entrance.
- Trace native inside wall faces, measured door openings and native slab support. Drawing outlines are identity/seed hints. Use independently registered drawing partitions only when their registration and floor support are proven.
- Native floor support is not indoor enclosure. Check bridges/links against actual facade/glazing, enclosure above the floor section and entry doors. Use Source model → Full model context to remove section clipping without changing GIS registration. The open outer slab-edge diagnostic is a review flag, not outdoor certification; missing curtain geometry can trigger it, and zero exposed edges does not certify indoors. Preserve real inner slab apertures and classify confirmed exterior connections separately from enclosed hallways. Do not repair a real outdoor edge as a missing wall.
- Close measured doors for **display** without closing their real route thresholds. Do not subtract architectural door swings from the floor or extend unlabelled wall gaps indiscriminately. Bounded gap-closure experiments are options requiring evidence, not universal rules.
- Keep real stair apertures, landings, treads, terminal risers, ramps and neighbouring rooms separate. Visible source-model stairs/elevator shafts do not verify routes or wheelchair access.
- Record manual classifications/merges in source review with model identity and provenance. Regenerate after source changes so routing and display share native boundaries. A rendering correction should preserve the safe original navigation interior.
- Investigate zoom-dependent fragments/coplanar striping and native curtain-host fallback extents in both display and routing. Numerical cleanup must not delete real narrow geometry.
- Save evidence notes and decisions in the reviewed master. Marking “Reviewed” does not repair a missing enclosure or admit a route; stale geometry-bound decisions need a new review.

## Complete the review

For shutters, pickup fronts and doorless entrances, use `reviewedAreaPartitions` in **Native areas → Define open entrances and partitions**. Separate the logical area boundary from physical wall repair and navigation permissions. Save a proposal, preview each line with current native geometry, and explicitly apply only to selection after floor/opening, original endpoint and obstacle checks. Record human assumptions as provisional; do not fabricate a physical wall, change access or certify a raised enclosure from a virtual closure. Keep routing and physical doors unchanged; preserve source/prepared descriptor parity and authoring ZIP portability. For shafts use a reviewed non-traversable footprint, preserve real holes and lift lobbies, and investigate served entrances/connectors separately. See the open-entrance workflow in native area review.

Run the shared audit on the current ZIP, investigate scoped records, implement supported corrections, and test actual door approaches plus relevant multifloor paths. Compare 2D/3D/source-model rendering across zooms on desktop and mobile. Preserve source RVT/GLB/GIS bytes, unrelated arrivals and connector ownership; report unresolved cases explicitly.

Use a task-specific candidate directory and a hash check before promoting the canonical master. Reconcile another chat's newer master rather than overwriting it. The full master is the authoring file; the campus viewer is derived. Existing user authorization governs publishing and cross-chat messaging.

For folder import, native region selection, labels and classification decisions, read [native area review](../../../docs/native-area-review.md). The native selection worker closes measured doors only for selection. Keep proposals separate from explicit application; applying changes complete checked source identities, not invented clipped routing areas. Geometry/access changes invalidate prepared circulation and require regeneration. Preserve checksummed companion provenance and model/scene/GIS bytes; never apply a stale selection or treat an approximate curtain envelope as a wall.

When a native selection unexpectedly spans rooms, distinguish excluded polygon holes from actual shared floor components. Check the aperture-side diagnostics and source label seeds: a same-region door check indicates connectivity, not a defective Revit door; the bypass may be at a different wall join. Inspect the native reference before extending a wall or closing a gap. Do not automatically preselect contained place identities for access changes.

For wall-gap controls, use the conservative aligned-cap detector as an experiment. Default zero; compare thresholds and report unresolved joins rather than declaring every contained label fixed. Preserve native slab holes and measured portals. Room focus may use a source crop and must disclose that provenance. Temporary preview IDs never authorize classification or source patches. Save individual evidence-backed recommendations in `nativeBoundaryPatches`; applying adds tagged derived wall faces while preserving RVT/GLB/GIS and blocks directions/viewer export until the sibling Reviter compiler regenerates. Validate model identity, exact supporting wall footprints, patch state and derived tags. Test native prepass plus physical circulation and portable round trips. Compare exact partitioned overlays across zooms on desktop/mobile; original rings must remain unchanged. Save threshold counts, raw candidates and visual proof with checksums in the canonical master companion folder without relabelling old scans or overwriting the master.

For indoor-only scope, use Native slab focus to inspect exact bridge/slab footprints, then the explicit Outdoors classification after verifying the whole selection in full source context. Keep a proposal separate from application. Applied `indoorExclusions` must match in authoring room metadata and the dataset, bind the model/native elevation, preserve physical source geometry, and affect both selection and every indoor route profile. Test thin segment crossings, hole interiors, arrivals, alternate indoor routes, other floors, cache invalidation, portable ZIPs and restoration on desktop/mobile. Reviter must subtract the same mask from derived circulation. Do not bulk classify exposed-edge flags as outdoors or change an entire contained room because part of a slab lies outdoors.

Use **Native areas → Find narrow connections** or `scripts/indoor/scan-native-connections.ts` for measured bottleneck investigations. Read the detector limits in `docs/native-area-review.md`: distinguish a single separating cut from a combined experiment, disclose partial scans, retain holes and measured doors, and pass supported repairs through the existing full-thickness wall checks. A narrow cut is not an approved wall. Use **Pin recommendations** for evidence-bound authoring replies; accepting a recommendation is separate from applying geometry. Save scans and decisions as checksummed companions, exclude them from visitor exports, and refresh stale evidence after geometry changes.

For per-patch review, use **Pin review → Review patches one by one**. A saved acceptance is authoring metadata, not source application. Preview only current accepted patches together; `pin-review/patch-decisions.json` binds each reply to recommendation evidence, dataset geometry and exact patch bytes. Export it with the reviewed master and exclude it from visitor assets. Changing patch or evidence invalidates the decision. Follow `docs/native-area-review.md` for the individual/accepted comparison flow and separately checked geometry application.

Room proposals also have shared **Accept proposal / Reject proposal / Needs more evidence** controls in Room review and Native areas → Saved boundary patches → Review decision. The portable `room-review/proposal-decisions.json` companion binds current audited geometry, proposal text and exact patch bytes; identical patch sets share one decision. Use Copy/Download proposal decisions to hand responses back to the reviewing chat. An acceptance alone does not apply source geometry. Follow explicit user scope when applying a checked repair, regenerate, verify affected rooms and doors, and preserve the old evidence and unrelated replies.

For a confirmed inaccessible lip behind a railing/glazing edge, use a checked exact `indoorExclusions` footprint with `reason: "off-limits"`; omitted reasons remain legacy outdoors. Compare the source railing, glass, slab holes and endpoints, and retain occupied rooms and door/stair approaches outside the mask. Native floor support does not make the lip traversable. Save a proposal separately from application, regenerate circulation, and verify both selection and every route profile while preserving floors, room identities/access and model/GIS bytes. Do not label an indoor void edge outdoors or apply small glazing seam patches merely because they increase a repair count. The existing Off limits place classification changes checked place walkability; Exclude non-traversable footprint preserves places and records a geometric scope veto.

If certified native curved column recovery exposes a missing wall join, preserve the true curve and audit previously raised blocks. Repair only an evidenced original-axis full-thickness cap to the first consecutive certified convex column face contacts, then regenerate and compare both height modes. Do not restore an approximate box or copy stale display blocks to hide a regression.

For a measured unmatched doorway with one known original room side, a strictly checked selection-only threshold endpoint correction can use `selectionBarrierOnly: true`; preserve its unmatched state and absent portal. Follow the exact finite-jamb and floor guards in native area review. A successful room mask does not resolve the missing doorway arrival.

Exact column cap chains may preserve notches outside the contacted strip. Require a simple original native column outline, a consecutive locally convex chain containing every intervening original vertex, monotonic lateral coordinates and the first actual column contact across the entire wall width. Test all projected original column vertices and interval midpoints; two endpoint rays alone cannot certify a nonconvex support. Preserve the original column profile and use only bounded cap contact overlaps.

A connected two-sided physical door with its existing supported portal may explicitly declare `measuredTangentLimitFeet` from 0.15 to 0.2 ft for a documented measured jamb miss. The default remains 0.15 ft; unmatched selection barriers cannot use this exception. Both finite original jambs, unchanged normal depth, bounded penetration and every floor/opening/foreign-obstacle guard still pass. Record the exact measured extent and independent physical proof; this field cannot create a portal, change access or widen a normal-depth footprint.

If the human explicitly authorizes a construction assumption for a missing boxed entry, use a separately logged reversible `assumedEnclosureProof` with three independently registered outer faces and a declared assumed closing face. Keep native floor/opening, physical door, column/fixture and support checks; regenerate. Label its proposal and successful enclosure provisional, count it separately from source-verified repairs and preserve the authorization/revisit requirement in the master and source recipe. Do not silently convert it to certified drawing evidence.

For a persisted physical door blocked by one original basic host, use the independently guarded `basic-host-missing-opening` aperture variant only with exact native host/door evidence and the unchanged enabled two-owner prepared portal. Preserve physical leaf bytes, source floor openings, foreign walls/columns, identity and access; regenerate. Its measured double-door width bound does not widen curtain-frame or overlapping-wall variants. A successful host-mask cut is separate from a fully connected pass-through selection; disclose remaining floor precision or approach failures.

For a historical wall continuation sharing an aperture-cut host, validate original evidence through the exact checked original-minus-aperture geometry, then require actual original contacts to remain on retained material and no doorway fill. Restore only explicitly bound full original faces, keeping exact current post-cut evidence in the proof copy for other continuations. Contextual wall evidence does not imply contact. Use proof-only original restoration; retain multipart cut geometry in native selection, routing and plan views. Never overwrite historical patch evidence or waive stale checks.
