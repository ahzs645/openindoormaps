## Implementation and integrity

- Startup fetches only the checked manifest, small search shell and selected overview. A small body-free shell HEAD enables Brotli when the host supplies exposed `Content-Encoding: br`. That choice follows detail and route requests into their workers. Raw gzip files work on an ordinary static host without custom headers. Actual full-size routing transport was checked in Chromium: 24,026,121 gzip bytes or 14,100,933 Brotli bytes expand to the identical 116,495,882-byte JSON, logical SHA `a7f91256cb2bbd8c6951d7fdab154d7f104c5e0c4bd0100b7e2abb1202cd3ddd`.
- Manifest, stored/expanded content, scope, original model/rooms and preparation-engine bindings are checked. Required lean fields and overview collections are checked before rendering. The importer supports the default gzip/Brotli inventory and older optional identity representations. Source identity compares values independently of JSON member order.
- Details use the existing prepared/native renderer. Source-bound auxiliary facts include flags, exact connector markers, labels, extrusions, ramp bodies/platforms/edge policy/nodes/datum, portal markers and stair selection ownership. No empty native authority substitutes for these facts. Overview projection repairs preserve actual holes and exclusions; auxiliary projection provenance is separate from the unchanged prepared engine.
- Before exposing a calculator, the private route worker runs `validateIndoorDataset` and the ordinary calculator inside the same immutable routing session. Checked indexes are reused without bypassing physical validation. Replacement clears previous authority atomically. Source access restrictions, unknown access, unconfirmed step-free connections, ordinary-room transit and visitor aliases use the existing shared policies.
- Floor decoding and route validation use cancellable tracked workers, scheduler teardown and lifetime locks. Stale map/floor/route generations cannot replace current state. Endpoint/profile changes clear instructions and disclosures. A stable adapter callback avoids unnecessary whole-floor layer effects on unrelated UI updates.
- Source decoding and displayed-floor readiness are separate. The visible drawing status waits for the current upload counts, loaded indoor sources, existing custom-mesh readiness and a later painted frame. It handles cancellation, replaced layers, failures and moving cameras. A new camera viewport can still need tiles after that generation becomes ready; screenshot capture explicitly waits for current viewport tiles and a later render.
- Verified content-addressed assets are compressed in IndexedDB with defaults of 512 MiB, 8,192 assets and 16 manifests. Recent decoded-floor retention is bounded to two entries / 128 MiB with conservative charging. Large floors remain only in the active view. These limits do not cap active renderer, GPU or routing memory.
- Complete offline download is explicit and resumable. Completion requires every verified asset and the exact retained manifest to coexist, a verified app shell, and final inventory readback. Partial manifests identify missing floors and cannot claim a complete map. Labels use same-origin bundled glyphs; the optional online street basemap is additional traffic.

## Remaining performance and visual limits

This is a delivery improvement, not a claim of fast cold routing or low-end mobile readiness. On the shared Chromium/software-WebGL host, a cold Library same-floor request took **715.666 seconds**, and a separate cold Theatre/Agora request took **380.532 seconds** including transfer/full validation/calculation. Query choice and warmed geometry affect subsequent timings; these are not comparable isolated speedup measurements. Responsive mobile screenshots demonstrate layout, not mobile hardware performance.

The final actual session sampled **4.35 GB sum of browser-process RSS** (GPU subset 302 MB) and **465 MB main JS used heap**. Shared pages can be counted more than once; worker heap samples often time out during synchronous work, making observed worker peaks incomplete lower bounds. Its native paint sources contain **93,905 features / 584,247 coordinate positions**, with another 2,128 prepared area/room features / 210,218 positions. Material paint alone accounts for 44,183 features / 269,021 positions. This supports a separate investigation of paint/picking separation, flat GPU paint or prebuilt tiles while preserving exact physical routing authority; no such further format change is claimed here.

The inspected large white-slit and grey-speck crops are repaired. A **17-pixel residual remains in one inspected 15,000-pixel mint crop**; a bounded depth-only experiment did not fix it, and no masking or source geometry change was applied. Authentic physical columns, openings and room surfaces remain visible. This work makes no zero-artifact or published-stair-approval claim.
