# Exact display partition proof

The production helper is `app/indoor-project/native-exact-display-boundary-proof.ts`; the prototype entry now re-exports that implementation. The version 3 published display validator uses its positive result after the existing schema, source binding, certificate, inventory and unchanged-anchor checks. A `proved: false` result runs the original exact polygon checks; it does not reject an otherwise valid map by itself. Routing, the source compiler and visitor cache trust are unchanged.

For one valid source polygon part S, independently valid numeric pieces Dᵢ and independently valid exact residual parts Rⱼ, each indicator is nonnegative and the source indicator is either zero or one. Normalize actual outer rings counterclockwise and actual holes clockwise. If the exact oriented boundary chain of ΣDᵢ + ΣRⱼ − S vanishes, its winding is constant on each plane cell and equal across every boundary. Compact support makes that constant zero. Therefore Σ1(Dᵢ)+Σ1(Rⱼ)=1(S) away from finite boundaries. This establishes positive-area source coverage, containment and absence of positive overlap. In particular the residual union equals source minus the numeric union, which is the existing validator's positive-area difference/XOR obligation. No positive gap, hole, sliver or overlap is discarded by a size threshold.

The proof does not establish additional closed-set physical clearance or navigation authority. Existing metadata, source binding, topology checks, face inventories, unchanged IEEE anchors and final dataset/mapping checksums must still execute. Routing continues using original exact source geometry.

Each exact rational supporting line is represented by primitive integer coefficients A,B,C with a fixed sign. An edge contributes a signed finite interval on an injective coordinate parameter of that line. Its lower endpoint adds the coefficient and its upper endpoint subtracts it. Every parameter event must cancel exactly. This is equivalent to splitting collinear intervals at every original endpoint; sorting and polygon intersections are unnecessary. Crossings between different lines cannot cancel a positive length of either line.

Validity is essential. The helper creates the original exact source/residual topology indices, retaining their simplicity, finite exact-coordinate, ring/edge, hole overlap and checksum guards. It additionally checks every complete hole edge against its shell with the original exact finite-segment cuts. This is necessary: the existing index's vertex-only shell containment and isolated endpoint-contact allowance can accept a hole that leaves a concave shell between boundary-contact vertices. The negative fixture exercises that case before any chain equality is accepted. The new unfrozen shell-only wrapper avoids the path helper's optional local tile overlay, so the stronger containment check itself uses exact point/segment predicates.

The source must contain exactly one polygon part. Existing topology validation does not prove pairwise source-component disjointness; multiple source parts therefore return an unresolved proof and keep the original fallback. Residual parts may overlap before checking: each part is independently nonnegative after stronger hole containment, and successful chain equality against a single source indicator then rules out any positive overlap. Residual ring orientation is normalized by its actual shell/hole role, never treated as signed permission to subtract an arbitrary polygon.

Numeric pieces must be finite, bounded, hole-free, nondegenerate convex polygons without repeated vertices. Every vertex is checked against every directed edge. Consistent local turns alone are insufficient because a self-crossing pentagram can satisfy that weaker test. Unsupported nonconvex numeric pieces use the original fallback. Rational scalar, edge, line-key, hole-check and time budgets also refuse conservatively.

The actual old largest face (`native-region:311:12`) has 3,402 source vertices, 2,787 numeric pieces and 810 residual parts. In the first bounded Node run, fresh original topology validation took 469 ms and the stronger positivity/chain proof took 1,694 ms, with 371 MB process RSS. It checked 1,377,787 hole-edge pairs and 20,726 directed segments; all line events cancelled. These are single-face measurements, not a complete importer speedup. The slow original overlay was not rerun. Raw results and exact source ZIP/mapping bindings are in `/workspace/scratch/unbc-pathway-repair-20261015/navigation-qa/render-boundary-proof-benchmark.json`.

Maximum sampled process RSS was 1.11 GB during load; sampled V8 heap use reached 289 MB under a 2 GiB process heap cap. This still excludes the rest of the importer and the original slow display overlay was not retried. Every region's geometry ID, result, reason, timing and check counts are saved in `navigation-qa/all-render-boundary-proofs.json`.
